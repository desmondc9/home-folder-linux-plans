# Phase 1 独立审阅与执行判断

独立全分支审阅初版结论为 With fixes；未发现候选配置/凭据API本身的缺陷，发现后端fixture与证书fixture两项覆盖盲点。本人单轮补充RED→GREEN测试并修复，未再次派审。最终13项纯测试+18项协议测试通过，3种错误候选变异均被门禁捕获。

## 判断与代价（按作出顺序）

| 判断 | 理由 | 若判断错误的代价 |
|---|---|---|
| 保留OpenCode原生worktree位置，不迁到.worktrees | 保持工具的工作区注册 | 仅目录不符合通用模板，不影响线上 |
| 以实际协议/监听验证替代源文本断言 | 配置字符串出现不能证明行为 | fixture可能遗漏业务细节，仍需现场验收 |
| 将证书fixture盲点从Minor提升到Important并修复 | 错lineage可能使真实站点TLS失败 | 多生成临时证书，增加少量测试时间 |
| 默认路由测试分离SNI与HTTP Host，保留Web后端身份断言 | 严格后端应拒绝未知Host，未知SNI并不等于未知Host | 若测试错误可能漏默认路由回归；身份断言和变异验证降低风险 |
| 备份/恢复、激活/watchdog、卸载留在阶段2/3 | 阶段1没有激活入口 | 不能据此直接安全上线；本阶段明确不部署 |
| KV写入、秘密交付、host-only CD留在阶段3 | 本阶段只确定输入契约 | 不代表凭据已部署；不能宣称整体完成 |
| 生产续期和证书fingerprint仍需现场验收；当前vhost其他指令已单独token对比 | 测试证书不是生产证据 | 仍可能有现场TLS差异，切换前后必须检查 |
| DNS/公网双栈/外部目标仍需外部验收 | 早前只读探测不保证未来用户网络可达 | 本机通过后仍可能外网不可用，不提前宣称成功 |
| 不自动跑OAuth E2E、持续长连接流量或额定吞吐压测 | 未请求业务E2E/负载，应用代码未变 | 后续可能需要定向业务/容量验收 |
| 不新增对恶意本机用户的隔离 | 设计明确接受回环为主机信任边界 | 恶意本机进程仍能连接回环端口 |
| renderer必须先调用validate_credentials | 直接构造dataclass不是不可信输入入口 | 未来renderer若绕过会漏校验，阶段3须测完整入口 |

## 已修复

- 假后端现在有独立端口身份、Host/path白名单，错应用返回421，错health路径返回404；原先按Host伪装健康响应的盲点已关闭。
- 每个证书lineage使用真实域名分组的独立临时证书；错证书选择会触发hostname验证失败。
- 3种变异验证：auth上游4444误指4433、health路径误写、auth证书误用reading lineage，均使对应测试失败；这属于预期负例，不是生产故障。
